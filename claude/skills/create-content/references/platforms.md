# Platform Rules — Jagadesh Content Engine

## LinkedIn

### Format Rules
- Short paragraphs. Max 3 sentences per paragraph. Often 1–2.
- Hook in the very first line — no exceptions.
- No headers for short posts (under 200 words).
- Numbered insights are acceptable for medium/long posts IF each item has
  real substance (not padding).
- Max 2 hashtags, only if they feel completely natural. Never forced.
- One blank line between paragraphs for readability.

### Hook Types (first line options)
- A surprising statement: "Most engineering orgs are slow for the same reason."
- A specific number: "We reduced cloud costs by $200K/month. That wasn't
  the win."
- A counter-intuitive claim: "The compliance work was the easy part."
- A direct opener: "I made an org design decision in 2022 I'd make
  differently today."

### Lengths
- **Short (100–150 words):** Single insight, punchy, no structure needed.
  Often the most powerful format.
- **Medium (200–320 words):** 2–3 insights or a short story with a lesson.
  Light structure OK.
- **Long (350–500 words):** Deep story or framework post. Use numbered
  lessons or clear line breaks between sections. No headers.

### Closing
- A question that invites genuine reflection, OR
- A statement that lands and doesn't need a response
- NEVER: "Like and share if you agree" / "Drop a comment below" /
  "What do you think?" (too generic)

### Output Format
Output ONLY the post text. No preamble. No "Here's your post:". No
explanation after. Just the post, ready to copy-paste.

## X / Twitter Thread

### Format Rules
- 5–7 tweets. Never fewer than 5. Never more than 7.
- Each tweet STRICTLY ≤ 280 characters. Count carefully.
- Number each tweet: `1/`, `2/`, `3/` etc.
- One idea per tweet. No padding. No filler.
- No hashtags unless essential (max 1 per thread, last tweet only).

### Structure
- **Tweet 1 (Hook):** Must stop the scroll. Same hook rules as LinkedIn.
  Often the LinkedIn hook adapted to ≤280 chars.
- **Tweets 2–6 (Body):** One clear point per tweet. Short. Sharp.
  Each should be able to stand alone but builds on the previous.
- **Tweet 7 (Landing):** A question or a statement that sticks. This is
  what people screenshot.

### Character Counting
Before finalising, mentally verify each tweet is under 280 characters.
URLs count as ~23 characters on X regardless of actual length.

### Output Format
Output ONLY the numbered tweets. Nothing else. No preamble. No explanation.
Example:
```
1/ Most platform teams are excellent engineers building things nobody uses.

2/ They solved the wrong problem.

3/ Platform success isn't a technical challenge. It's an adoption challenge.
...
```

## Website Essay

### Format Rules
- **Length:** 800–1500 words. Written to be read, not skimmed.
- **Output format:** Markdown. `# Title` on line 1.
- **Subheadings:** Use `##` to break major sections. Subheadings should be
  direct and clear — no clever wordplay, no questions as headings.
- **Paragraphs:** 3–5 sentences. Full prose. No bullet lists in the body
  unless listing truly discrete items.

### Structure
1. **Opening (no heading):** A strong, specific claim or scene. NOT a
   rhetorical question. NOT a vague setup. Something that makes the reader
   think "I need to keep reading."
2. **Body sections (##):** Evidence from real experience, frameworks,
   specific examples. Each section builds the argument.
3. **Closing (## Conclusion or relevant heading):** Reframes the opening
   claim — doesn't summarise it. The reader should feel the argument has
   completed a full circle.

### Tone for Essays
- **Deep analysis:** Start with the thesis. Systematically dismantle the
  conventional wisdom. Build the alternative framework with evidence.
- **Story-led:** Open with a specific scene or moment. Build the lesson
  through narrative. Extract the framework at the end.
- **Practical guide:** Open with the problem. Walk through the solution with
  concrete steps. Close with the underlying principle.

### Output Format
Output the full essay in markdown. Include `# Title` on line 1.
No preamble. No "Here's your essay:".

## Website Hook Rules

The hook is added to the END of LinkedIn posts and X threads to drive traffic
to jagadeshbabu.com. It is NEVER added to website essays (no point linking
to itself).

### When to Add
Only when Jagadesh explicitly requests it (via toggle or asking).

### The Hook Must
- Feel like a natural, contextual invitation — not a generic CTA
- Tease what is specifically deeper on the site: the full framework, the
  complete case study, the exact playbook, the templates
- Be specific to the content of that post — not boilerplate

### LinkedIn Hook Format
One short sentence on its own line, then the URL on the next line.

```
The full three-part framework — including the exact conversations I have
before any platform launch — is on my website.
jagadeshbabu.com/platform-adoption
```

### X Hook Format (last tweet)
One sentence ≤240 characters including the URL. Number it as the last tweet.

```
7/ I broke down the complete architecture decision process with the
tradeoffs we actually faced: jagadeshbabu.com/cloud-native-banking
```

### URL Format
- With slug: `jagadeshbabu.com/[slug]`
- Without slug: `jagadeshbabu.com`

### GOOD hook examples
- "The full framework — including the three conversations I have before any
  reorg — is on my website.\njagadeshbabu.com/org-design"
- "I wrote up the complete playbook with the exact questions I use:
  jagadeshbabu.com/hiring-bar"
- "The detailed case study with every architecture decision is here:
  jagadeshbabu.com"

### BAD hook examples (never use)
- "Check out my website!" ← too generic
- "Link in bio!" ← wrong platform behaviour, too casual
- "Read more at jagadeshbabu.com" ← no tease, no reason to click
- "Full post at jagadeshbabu.com" ← sounds like a cross-post, not a hook

## Cross-Platform Adaptation Rules

When adapting content from one platform to another:

**LinkedIn → X thread:**
- Extract the core insight and the 3–5 supporting points
- Compress each into one tweet
- Rewrite the opening as a hook tweet
- Add landing tweet at the end
- Preserve all specific numbers and facts

**LinkedIn → Website essay:**
- Expand from the hook and core insight
- Add the full context, background, and evidence that the post couldn't fit
- Add subheadings and structure
- The post's closing question often becomes the essay's opening claim

**X thread → LinkedIn:**
- Combine the tweet points into flowing prose
- Add the context and nuance that tweets couldn't hold
- Rewrite as short paragraphs with the hook in line 1

**Website essay → LinkedIn or X:**
- Extract the single most powerful insight from the essay
- Build the post/thread around that one insight
- Add the website hook linking back to the full essay
- Do NOT try to summarise the whole essay — pick one thread to pull

**Preserve always:**
- All specific numbers and metrics
- Real facts from Jagadesh's background
- The core argument and contrarian stance
- The voice and tone
